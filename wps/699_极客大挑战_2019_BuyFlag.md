# [极客大挑战 2019]BuyFlag

## 题目概述
购买Flag需要满足三个条件：CUIT学生身份、正确密码、足够金额。页面注释泄露了PHP源码，暴露了密码验证逻辑和类型混淆漏洞。

## 信息收集
访问首页 `index.php`，发现导航栏有 `pay.php` 链接。

访问 `pay.php`，页面提示：
- Flag 需要 100000000 money
- 必须是 CUIT 学生
- 必须回答正确密码

**关键发现**：页面 HTML 注释中泄露了 PHP 源码：

```php
~~~post money and password~~~
if (isset($_POST['password'])) {
    $password = $_POST['password'];
    if (is_numeric($password)) {
        echo "password can't be number</br>";
    } elseif ($password == 404) {
        echo "Password Right!</br>";
    }
}
```

响应头 `Set-Cookie: user=0` 和 `X-Powered-By: PHP/5.3.3` 提示身份验证通过 cookie 控制，且 PHP 版本古老。

## 漏洞分析

**漏洞类型**：PHP 弱类型比较 + 数组参数绕过

**核心原理**：
1. **密码绕过**：`$password == 404` 使用了 `==` 弱比较。`is_numeric()` 拦截纯数字字符串，但 `"404a"` 不是纯数字，同时 `"404a" == 404` 在 PHP 中为 `true`（字符串被隐式转为整数）。
2. **身份伪造**：`Set-Cookie: user=0` 暗示 cookie 控制身份，设置 `user=1` 即可伪装为 CUIT 学生。
3. **金额绕过**：直接传 `money=100000000` 会被 "Number length is too long" 拦截。传 `money[]=100000000`（数组）可绕过长度检查，且 PHP 中数组与数字的比较结果异常，满足金额条件。

## 利用过程

**Payload**：
```bash
curl -s -X POST "http://target/pay.php" \
  -b "user=1" \
  -d "password=404a&money[]=100000000"
```

**Flag**：`flag{22907809-97f4-453d-9248-1e867fa80d4a}`

## 复现步骤
1. 访问 `pay.php`，查看页面源码注释获取 PHP 逻辑
2. 观察响应头 `Set-Cookie: user=0`，推断身份验证机制
3. 构造 POST 请求：`password=404a` 绕过 `is_numeric` + 弱比较，`money[]=100000000` 绕过长度检查，Cookie 设置 `user=1` 伪造身份
4. 发送请求，获取 flag

## 技术总结

| 漏洞类型 | 攻击入口 | 核心 Payload | 知识点 |
|---------|---------|-------------|-------|
| PHP 弱类型比较 | password 参数 | `password=404a` | `==` 隐式类型转换，`"404a" == 404` 为 true |
| 数组参数绕过 | money 参数 | `money[]=100000000` | PHP 数组与标量比较行为异常 |
| Cookie 身份伪造 | Cookie 头 | `user=1` | 响应头泄露 Set-Cookie 逻辑 |

## 知识总结
- PHP `==` 弱比较是经典考点：字符串与整数比较时，字符串从头解析数字部分，`"404a" == 404` 为 true
- `is_numeric()` 可被含数字的非纯数字字符串绕过（如 `404a`、`404 `、`0x194` 等）
- PHP 中数组与数字比较时行为不可预测，常用于绕过数值大小检查
- 页面注释、响应头（`Set-Cookie`、`X-Powered-By`）是重要信息泄露源
