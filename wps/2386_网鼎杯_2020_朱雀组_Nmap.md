# [网鼎杯 2020 朱雀组]Nmap

## 题目概述
题目是一个 Nmap 在线扫描工具，用户可以输入主机名或 IP 地址进行端口扫描。页面注释提示 flag 位于 `/flag` 文件中。

## 信息收集
1. 访问题目首页，发现是一个 Nmap 扫描表单，POST 参数为 `host`
2. 页面源码注释：`<!-- flag is in /flag -->`
3. 存在 `/list.php` 可查看扫描结果文件列表
4. 存在 `/result.php?f=xxx` 可查看具体扫描结果

## 漏洞分析（漏洞类型、原理、判断过程）
**漏洞类型**：命令行参数注入

**原理**：
- 后端将用户输入的 `host` 参数直接拼接到 nmap 命令中
- Nmap 的 `-iL` 参数可以从文件读取目标列表
- 通过单引号闭合原有命令，注入 `-iL /flag` 参数读取 flag 文件
- 同时使用 `-oN flag.txt` 将输出重定向到可访问的文件

**判断过程**：
1. 测试输入 `127.0.0.1 -oN test.txt`，发现参数被成功执行
2. 查看 list.php 发现新的结果文件生成
3. 尝试使用 `-iL /flag` 读取 flag 文件

## 利用过程（Payload + Flag）

**Payload**：
```
host=' -iL /flag -oN flag.txt '
```

**原理**：
- 单引号 `'` 闭合原有的 host 参数
- `-iL /flag` 让 nmap 从 /flag 文件读取内容作为目标
- `-oN flag.txt` 将扫描结果输出到 flag.txt 文件
- 最后的单引号闭合命令

**获取 Flag**：
访问 `http://target/flag.txt`，在 nmap 输出中看到：
```
Failed to resolve "flag{51b296c3-ab4f-48ab-8a50-0662b774ae97}".
```

Flag: `flag{51b296c3-ab4f-48ab-8a50-0662b774ae97}`

## 复现步骤
1. 访问题目页面，发现 Nmap 扫描功能
2. 构造 Payload：`' -iL /flag -oN flag.txt '`
3. POST 提交：`host=' -iL /flag -oN flag.txt '`
4. 访问 `/flag.txt` 获取 flag

## 技术总结（表格：漏洞类型/攻击入口/核心Payload/知识点）

| 漏洞类型 | 攻击入口 | 核心 Payload | 知识点 |
|---------|---------|-------------|--------|
| 参数注入 | host 参数 | `' -iL /flag -oN flag.txt '` | Nmap -iL 参数可读取文件 |

## 知识总结（解题技巧、同类题型套路）
1. **Nmap 参数利用**：
   - `-iL <file>`：从文件读取目标列表（可用于读取任意文件）
   - `-oN <file>`：输出正常结果到文件
   - `-oX <file>`：输出 XML 格式结果

2. **参数注入套路**：
   - 先测试参数是否可控（如 `-oN test.txt`）
   - 利用单引号/双引号闭合原有命令
   - 注入目标参数实现攻击

3. **文件读取技巧**：当无法直接执行命令时，利用工具自带的文件读取功能（如 nmap 的 `-iL`）
